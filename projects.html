EXPLAINABLE AI · COMPUTER VISION · RESEARCH

MULTISPECTRAL
CROP STRESS.

An explainable AI system built with Sentinel-2 satellite imagery and Vision Transformers to detect crop stress before visible symptoms appear.

Why I built it: the work explores whether multispectral satellite information can be used to identify crop stress earlier, while still giving a person a visual explanation of what influenced the model's prediction. It was developed as a government-funded research project and became the basis of a co-authored 2025 publication.

WHAT GOES IN

Sentinel-2 multispectral satellite imagery.

WHAT HAPPENS

Visual information is processed through a Vision Transformer-based model to detect crop stress.

HOW I EXPLAIN IT

SHAP and Grad-CAM are used to create visual explanations around the model output.

EXTRA LAYER

A RAG-based chatbot was implemented as an additional project feature.

LLM · VOICE AI · MULTILINGUAL HEALTHCARE

PATIENT
ASSISTANCE.

A multilingual voice AI system supporting English, Arabic, Hindi and Malayalam for patient intake, appointment booking, returning-patient assistance and emergency escalation.

Why I built it: the goal was to make a patient-facing voice flow that could handle more than a single question-and-answer exchange. The system uses a state-driven conversation pipeline so the assistant can collect information, retrieve patient context, move toward booking, recommend a doctor, generate confirmations and escalate emergencies.

CONVERSATION

State-driven conversational pipeline for first-time and returning patients.

VOICE INPUT

Whisper and Deepgram are used within the documented voice pipeline for speech handling.

LANGUAGE MODEL

Groq-powered LLM processing generates the conversational response.

RESPONSE + DELIVERY

Edge TTS, SSE streaming, FastAPI, ReportLab and SMTP support the end-to-end flow.

RAG · INFORMATION RETRIEVAL · CULTURAL HERITAGE

CULTURAL
KNOWLEDGE.

A retrieval-augmented system that pulls information from multiple cultural heritage APIs and generates context-aware answers grounded in historical sources.

Why I built it: cultural information can live across different collections and APIs. Instead of treating one source as the entire answer, this build focuses on retrieving information from several sources, processing it, and keeping the generated response connected to those retrieved sources.

RETRIEVAL

Multi-source retrieval brings together relevant records before generation.

SOURCES

Europeana, Wikidata SPARQL and Smithsonian Open Access APIs.

GROUNDING

Responses are generated from retrieved historical information rather than only a free-form model response.

INTERFACE

Python, Pandas and Streamlit form the documented application layer.

COMPUTER VISION · HUMAN COMPUTER INTERACTION

GESTURE
CONTROL.

A real-time hand gesture system that maps visual hand movements to computer controls such as cursor movement, volume control and click operations.

Why I built it: the project explores a more direct interaction model where a camera becomes the input device. Instead of a conventional mouse-and-keyboard action, hand movement is interpreted as a control signal in real time.

VISION

OpenCV handles the live video processing pipeline.

TRACKING

MediaPipe hand tracking provides the hand landmark information.

CONTROL

Recognized gestures are mapped to cursor, volume and click operations.

DATA PATH

Camera frame → hand landmarks → gesture interpretation → computer action.
